# 健身塑形饮食推荐小程序（需求方案）

## 1. 目标用户
- 有减脂、增肌、体态管理需求的人群。
- 每天有运动记录（如跑步、力量训练、骑行）且希望把“训练消耗”与“饮食摄入”联动管理的用户。
- 有“家里现有食材想快速做饭”需求的用户。

---

## 2. 核心目标
1. **训练-饮食联动推荐**：接入运动软件后，根据当日运动消耗和个人目标（减脂/维持/增肌）推荐菜谱。
2. **食材反向找菜**：用户勾选家中已有食材，推荐可做菜谱并给出营养与热量信息。
3. **热量不超标控制**：系统给出用户“今日建议热量上限”，并对每餐/每个菜谱打分与预警。

---

## 3. 功能模块

### 3.1 用户与目标设定
- 用户首次输入：性别、年龄、身高、体重、目标体重、活动水平。
- 目标模式：
  - 减脂模式：建议每日热量赤字（例如 -300~-500 kcal）
  - 维持模式：热量平衡
  - 增肌模式：建议每日热量盈余（例如 +200~+400 kcal）
- 周目标设置：每周训练天数、每日饮食偏好（中式/低脂/高蛋白等）。

### 3.2 运动数据接入
- 对接运动平台 API（如 Apple Health、华为运动健康、Keep、Strava 等，实际以可用 SDK/API 为准）。
- 拉取数据：
  - 当日总消耗（kcal）
  - 运动类型、时长、强度
  - 历史7天/30天平均消耗
- 当用户未授权时，支持手动输入运动消耗。

### 3.3 食谱数据接入
- 接入海量菜谱源（开放菜谱 API、自建菜谱库、合作平台）。
- 每个菜谱结构化字段：
  - 菜谱名称
  - 食材清单（及克重）
  - 烹饪步骤
  - 每份热量（kcal）
  - 三大营养素（蛋白质/脂肪/碳水）
  - 口味标签（清淡、重口、酸辣等）
  - 适用目标标签（减脂/增肌/控糖）

### 3.4 AI 推荐引擎
#### 推荐场景 A：按运动消耗推荐
输入：用户今日剩余热量预算 + 训练类型 + 偏好 + 忌口。
输出：早餐/午餐/晚餐/加餐推荐组合。

#### 推荐场景 B：按现有食材推荐
输入：用户勾选家中食材（如鸡胸肉、鸡蛋、西兰花）。
输出：可做菜谱列表，按目标匹配度排序。

#### 推荐场景 C：混合推荐
在已有食材基础上，补充“需额外采购食材最少”的菜谱优先。

### 3.5 评分与指数体系
每个菜谱展示三个指数（0~100）：
1. **热量指数**（Calorie Index）
   - 与用户剩余热量预算匹配度越高，分数越高。
   - 若超预算明显，降分并预警。
2. **口味指数**（Taste Index）
   - 基于用户历史点赞/收藏/实际复做行为学习。
   - 符合偏好口味越多，分数越高。
3. **推荐指数**（Recommendation Index）
   - 综合热量、营养均衡、目标适配度、食材可得性、口味指数等得出。

可采用公式示例：

```text
推荐指数 = 0.35*热量匹配分 + 0.25*营养目标分 + 0.20*口味偏好分 + 0.10*食材可得分 + 0.10*用户行为分
```

### 3.6 每日热量上限与进度条
- 系统根据 BMR/TDEE + 目标模式，计算“今日建议摄入上限”。
- 首页显示：
  - 已摄入热量
  - 剩余可摄入热量
  - 若将超标，给出替换建议（更低热量菜谱）。

---

## 4. 热量计算逻辑（示例）

### 4.1 基础代谢（BMR）
可采用 Mifflin-St Jeor 公式：
- 男：`BMR = 10*体重(kg) + 6.25*身高(cm) - 5*年龄 + 5`
- 女：`BMR = 10*体重(kg) + 6.25*身高(cm) - 5*年龄 - 161`

### 4.2 每日总消耗（TDEE）
`TDEE = BMR * 活动系数 + 当日运动额外消耗`

### 4.3 目标热量上限
- 减脂：`摄入上限 = TDEE - 300~500`
- 维持：`摄入上限 = TDEE`
- 增肌：`摄入上限 = TDEE + 200~400`

> 备注：具体区间可由营养师策略配置，不建议给出极端赤字。

---

## 5. 小程序页面结构
1. **首页**：今日热量预算、运动消耗、推荐菜谱卡片。
2. **食材选菜页**：多选食材 -> 一键推荐。
3. **菜谱详情页**：热量指数、口味指数、推荐指数、步骤、营养信息。
4. **计划页**：每日三餐计划 + 打卡。
5. **我的页**：目标设置、忌口设置、平台授权管理。

---

## 6. MVP（最小可用版本）建议
第一阶段优先实现：
- 手动录入运动消耗（先不做复杂平台对接）
- 1000+结构化菜谱库
- 热量上限计算与超标提醒
- 食材选菜与基础推荐排序

第二阶段再增加：
- 多平台运动数据自动同步
- 个性化口味模型
- AI 对话式饮食助手（“今晚想吃高蛋白低脂”）

---

## 7. 示例用户流程
1. 用户授权同步今日运动消耗（例如 650 kcal）。
2. 系统计算今日可摄入上限（例如 2100 kcal），并显示已摄入 1200 kcal。
3. 用户晚餐前进入小程序，看到“剩余 900 kcal”。
4. 用户选择家里有“鸡胸肉+鸡蛋+西兰花”。
5. 系统推荐 5 个菜谱并展示三个指数，优先推荐高蛋白且不超标方案。
6. 用户选择菜谱后记录摄入，系统自动更新剩余热量。

## 8. 可直接复制使用的产品 Prompt（给 AI 助手/开发团队）

请设计一个面向“塑形/健身人群”的饮食推荐小程序，核心要求如下：
1. 接入运动软件数据（至少支持手动录入运动消耗，后续可扩展 API 对接），根据用户当天运动消耗与目标（减脂/维持/增肌）推荐三餐菜谱。
2. 支持“按现有食材推荐菜谱”：用户在小程序里勾选家中已有食材，系统推荐可制作菜品。
3. 系统要计算用户每日建议热量上限，并实时显示“已摄入/剩余可摄入”，当用户将超标时给出低热量替代菜谱。
4. 每个菜谱必须展示三个指数：热量指数、口味指数、推荐指数；并说明指数计算逻辑。
5. 给出小程序信息架构（页面与流程）、核心数据结构（用户、运动、菜谱）、推荐算法思路与 MVP 开发排期。
